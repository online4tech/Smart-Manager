# Online4Tech Smart Manager

واجهة أولية مستقلة لمنظومة Online4Tech Ecosystem، تبدأ بوحدة AI Doctor.

## الحالة الحالية
- React + Vite
- تصميم Modern Glass باللغة العربية وRTL
- Sidebar موحد للأقسام الأربعة
- AI Doctor dashboard يحتوي مؤشرات عرض تجريبية ما لم يُذكر غير ذلك
- Local Bridge يقرأ بيانات تعريف OpenWebif فقط عند إتمام الاتصال
- مكتبة البلجنات والأدوات منفصلة في `src/data/plugins.json` (836 سجلًا)
- مكتبة أوامر التثبيت والإزالة منفصلة في `src/data/commands.json` (1,276 أمرًا)
- تعرض مكتبة الأوامر أوامر التثبيت والإزالة للنسخ اليدوي، دون تنفيذ تلقائي من الواجهة

## التشغيل محلياً
يتطلب Node.js حديثاً.

```bash
npm install
npm run dev
```

لإنشاء نسخة إنتاجية:

```bash
npm run build
npm run preview
```

## هيكل المشروع
```text
src/
  data/demo.js       # بيانات العرض التجريبية
  data/enigma2-catalog.json # الملف الأصلي المستورد
  data/plugins.json      # مكتبة البلجنات والأدوات
  data/commands.json     # مكتبة أوامر التثبيت والإزالة
  App.jsx            # الواجهة الرئيسية
  main.jsx           # نقطة تشغيل React
  styles.css         # الهوية البصرية والتجاوب
```

## مراحل التطوير التالية
1. اعتماد الواجهة وتجربة العرض على الكمبيوتر والموبايل.
2. إضافة اختبارات واجهة وبناء production.
3. إنشاء طبقة API مستقلة بواجهات mock/real قابلة للتبديل.
4. ربط Local Bridge الحالي بعد مراجعة بروتوكوله وأمانه.
5. استبدال البيانات التجريبية ببيانات حقيقية مع الحفاظ على فصل واضح بين الوضعين.

## قواعد الأمان
- لا تضع كلمات مرور أو مفاتيح اتصال في الواجهة.
- لا تعرض بيانات تجريبية على أنها قراءات حقيقية.
- أي عملية تغيّر حالة الرسيفر تحتاج موافقة صريحة.
- لا تفتح Bridge أو SSH مباشرة على الإنترنت.


## النشر على GitHub Pages

يتم البناء والنشر تلقائياً عند كل تحديث على فرع `main` من خلال GitHub Actions.

- مسار Vite مضبوط على `/Smart-Manager/` ليتوافق مع رابط المشروع.
- يتم تثبيت الاعتماديات باستخدام `npm ci` ثم تنفيذ `npm run build`.
- يتم نشر مجلد `dist` كـ GitHub Pages artifact.
- يمكن تشغيل النشر يدوياً من تبويب Actions عبر Workflow باسم **Deploy Smart Manager to GitHub Pages**.

رابط الموقع المتوقع:
https://online4tech.github.io/Smart-Manager/

إذا لم تكن Pages مفعّلة بعد، افتح Settings → Pages وتأكد أن Build and deployment → Source مضبوط على **GitHub Actions**.


## AI Doctor – محلل السجلات المحلي
- يمكن لصق جزء من سجل Enigma2 داخل محلل السجلات.
- تتم المطابقة محليًا داخل المتصفح مع أنماط عامة لمساحة التخزين والذاكرة والإضافات والخدمات والشبكة والموالف.
- لا يتم رفع السجل إلى خادم، ولا يُحفظ بعد تحديث الصفحة.
- احذف كلمات المرور وعناوين IP العامة وأي بيانات شخصية قبل لصق السجل.
- النتائج إرشادية وتعتمد على كلمات مفتاحية، ولا تمثل تشخيصًا نهائيًا.
- المحلل لا ينفذ أوامر ولا يعدّل ملفات الجهاز.

## المرحلة القادمة: تكامل Bridge للقراءة فقط
قبل تفعيل أي اتصال حقيقي، يجب توثيق ومراجعة واجهات Bridge الحالية، ثم اعتماد:
1. مصادقة محلية واضحة وعدم تخزين كلمات المرور في الواجهة.
2. قائمة سماح لطلبات القراءة فقط.
3. منع تنفيذ shell/SSH أو عمليات الكتابة من واجهة الويب.
4. مهلة اتصال ورسائل أخطاء مفهومة، مع إظهار حالة الاتصال الحقيقية.
5. موافقة منفصلة قبل أي وظيفة مستقبلية تغيّر إعدادات الرسيفر.


## Local Bridge بدون أكواد ربط

- الجسر يحتفظ برمز ثقة محلي داخل ملف إعدادات المستخدم على الكمبيوتر.
- أول مرة فقط: يضغط المستخدم «اتصال آمن بالجسر» من الموقع؛ لا توجد كلمة مرور أو أرقام اقتران.
- المتصفح يحتفظ ببيانات الثقة في Local Storage، ويمكن مسح بيانات الاتصال المحفوظة من المتصفح؛ ملف الثقة المحلي يظل محفوظًا في مجلد المستخدم.
- خادم الجسر يستمع على `127.0.0.1` فقط، ويقبل Origin الموقع الرسمي المحدد.
- هذه الآلية مخصصة للاتصال المحلي من المتصفح نفسه، وليست مصادقة عن بُعد.
- بيانات OpenWebif تظل قراءة فقط. لا توجد حتى الآن واجهة SSH أو تنفيذ أوامر أو تثبيت/حذف.

## حزمة Windows الخلفية

يُبنى الملف التنفيذي عبر GitHub Actions باسم **Build Online4Tech Bridge for Windows**:
1. افتح تبويب Actions في المستودع.
2. شغّل workflow يدويًا أو افتح تشغيل PR ناجحًا.
3. نزّل artifact باسم `Online4Tech-Bridge-Windows`.
4. فك الضغط وشغّل PowerShell على `install-windows.ps1` من مجلد الحزمة.
5. ينسخ المثبّت البرنامج إلى مجلد المستخدم ويضيف اختصارًا إلى Startup؛ لا يحتاج صلاحيات Administrator.
6. لإزالته شغّل `uninstall-windows.ps1`.

الجسر يعمل في الخلفية بعد تسجيل الدخول إلى Windows. لا تغلقه يدويًا من Task Manager أثناء استخدام الموقع.

## التحضير لتثبيت البلجنات على الرسيفر

التثبيت الفعلي غير مفعّل في هذه المرحلة. قبل تفعيله يجب إكمال:
1. قناة SSH محلية بمفتاح عام/خاص، مع بقاء المفتاح الخاص على كمبيوتر المستخدم.
2. إدراج المفتاح العام على الرسيفر بموافقة مالكه، والتحقق من بصمة المضيف.
3. سجل حزم معتمد يحتوي معرّف الحزمة واسمها وإصدارها ومصدرها وبصمة الملف ومتطلبات توافق صورة Enigma2.
4. تنفيذ محدود عبر وسيط حزم معروف وبوسائط منفصلة، دون shell عام أو `wget | sh` أو أوامر إزالة.
5. تأكيد واضح لكل عملية، وتسجيل النتيجة، وإيقاف التنفيذ عند أي اختلاف في البصمة أو التوافق.

**مهم:** كتالوج الأوامر الحالي يحتوي سكريبتات خارجية غير مناسبة للتنفيذ الآلي. لذلك لن يرسل الجسر هذه الأوامر إلى الرسيفر، ولن يظهر زر تثبيت فعلي لعنصر غير موجود في سجل الحزم المعتمد.


## إصدار Windows الدائم للجسر
- مع كل تحديث ناجح على `main`، يبني GitHub Actions حزمة Windows وينشر إصدارًا جديدًا تلقائيًا، ويحدّث رابط Latest للزوار.
- يحتوي الإصدار على `Online4TechBridge.exe` وملفي التثبيت والإزالة، بالإضافة إلى `SHA256SUMS.txt` للتحقق من سلامة التنزيل.
- رابط التحميل الثابت للواجهة: https://github.com/online4tech/Smart-Manager/releases/latest/download/Online4Tech-Bridge-Windows.zip
- زر تثبيت البلجنات يظل غير مفعّل حتى اعتماد الحزمة والتحقق من توافقها؛ تنزيل الجسر وحده لا يعني أن تثبيت البلجنات أصبح متاحًا.
